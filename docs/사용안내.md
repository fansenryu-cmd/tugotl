# 투고틀 사용 안내

[README](../README.md)의 핵심 안내를 자세히 풀어 쓴 문서입니다. 프로그램 안의 **사용법·도움말** 메뉴에도 같은 내용이 있습니다. *English follows the Korean.*

## 내려받기와 확인

코드를 볼 필요가 없다면 저장소를 내려받지 마시고 배포본 하나만 받으면 됩니다.

1. **[내려받기 — tugotl.html](https://github.com/fansenryu-cmd/tugotl/releases/latest/download/tugotl.html)** (최신 배포본, 약 30 MB. [배포 페이지](https://github.com/fansenryu-cmd/tugotl/releases/latest)). 같은 파일이 저장소의 [release/투고틀.html](https://github.com/fansenryu-cmd/tugotl/blob/main/release/투고틀.html)에도 있습니다.
   - 또는 웹에서 바로 열기: **https://fansenryu-cmd.github.io/tugotl/** 의 ‘웹에서 바로 열기’(같은 파일을 GitHub Pages로 띄운 것. 열어 둔 뒤 인터넷을 끊어도 됩니다.)
2. 받은 `tugotl.html`(또는 `투고틀.html`)을 Chrome 또는 Edge에서 더블클릭으로 엽니다. HWP 엔진(rhwp, WebAssembly)·학회 양식 34개·투고 서식 15개가 전부 안에 들어 있어 **설치도, 인터넷도 필요 없습니다.** 원고는 PC 밖으로 나가지 않습니다.
3. 확인(선택): 파일 옆의 [`투고틀.sha256`](https://github.com/fansenryu-cmd/tugotl/blob/main/release/투고틀.sha256)과 비교합니다. 윈도우 PowerShell: `Get-FileHash .\투고틀.html -Algorithm SHA256`

받은 파일을 열 때 브라우저가 "인터넷에서 받은 파일" 경고를 낼 수 있습니다. 파일 안에는 외부 접속이 전혀 없습니다(CSP로 `connect-src`를 `data:` `blob:`으로 제한). 새 버전은 같은 자리에서 다시 받으면 됩니다. 사용법은 프로그램 안의 **사용법·도움말** 메뉴에 있습니다.

## 화면과 흐름

왼쪽 사이드바에서 **투고처 선택** → 하위 메뉴 **투고 양식 및 규정 확인** / **투고처 이동(JAMS 등)**.
오른쪽 작업 화면에 원고를 끌어다 놓으면 즉시 열리고 문단 역할(제목·초록·주제어·장 제목·본문·인용·참고문헌·영문초록)이 인식됩니다 → **적용** → 미리보기 / 정오표 / 변경 사항 / 투고 전 확인 → **저장**(저장 위치를 그때그때 고름).

- **설정** 여섯 가지뿐: 서지 양식(학회 규정 / APA / Chicago / 원고 그대로), 체재 순서 재배열, 저자·소속 제외(익명 원고), 원고 빈 줄 유지, 각주·참고문헌 정오표, 목차 자동 생성.
- **정오표**: 각주 인용 ↔ 참고문헌 대조(참고문헌에 없는 인용, 규정 양식과 어긋난 표기, 인용되지 않은 참고문헌)를 규칙으로 찾아 산출 HWP에 붉은 글자로 표시. 오자 확인은 항목별 Scholar·RISS·KCI 검색 링크로 직접.
- **투고 양식 및 규정**: 투고 시스템 주소, 제출 서류, 내장 신청서·동의서·서약서(내려받기), 규정 원문 링크, 체재·분량·초록 규정, 일정(공고 메일을 붙여 넣으면 다음 마감 갱신), 편집 양식 수치, 각주·참고문헌 규칙, 바탕틀 역할 매핑.
- **학회 추가**: JSON 한 덩어리 + 바탕틀 .hwp로 학회를 추가(이 브라우저에만 저장, 내보내기·가져오기).
- **목차 자동 생성**: 원고에 목차가 없고 학회 체재에 목차(차례)가 있으면 장 제목으로 목차를 만들어 넣습니다(설정에서 끌 수 있음). 인용문 앞뒤에는 한 줄을 띄우고, 바탕틀 예시의 쪽 나눔(참고문헌·영문초록이 새 쪽에서 시작)을 그대로 따릅니다.
- **정오표 설명**: 미리보기에서 붉게 표시된 글자에 마우스를 올리면 어떤 점이 어긋났는지 보입니다. 적용이 끝나면 왼쪽 아래에 “프로그램 규칙에 따른 편집이므로 저자가 직접 확인해 주세요”라는 안내가 뜹니다.
- **글꼴**: 투고틀은 글꼴 파일을 포함하지 않습니다(저작권). 산출 HWP에는 학회가 지정한 글꼴 이름이 그대로 기록되어 내 PC에 글꼴이 없어도 투고에는 지장이 없습니다. 학회별 필요 글꼴과 구하는 곳은 [docs/글꼴안내.md](글꼴안내.md).
- **미리보기의 한계**: 미리보기 엔진(rhwp)은 각주가 많은 쪽에서 본문 줄을 다음 쪽으로 넘기지 못해 본문과 각주가 겹쳐 보일 수 있습니다. 해당 쪽에는 노란 표시가 붙습니다. 저장한 HWP는 한글이 열 때 다시 배치하므로 겹치지 않습니다.
- **하단 문서정보 바**: 글자 수(공백 제외 포함)·각주 수·200자 원고지 환산 매수·학회 규정 매수와 초과/여유 매수·적용 후 쪽수를 한 줄로 표시. 초과분은 알려 줄 뿐 내용을 줄이지 않습니다.
- **Word(DOCX)로 저장**(v2.0): ▾ 메뉴에서 한글 산출물과 같은 용지·여백·글꼴·크기·장평·자간·줄 간격·들여쓰기·각주(번호 꼴·구분선)·표·그림을 Word 문서로 저장합니다. Word로 받는 학회나 해외 공동 저자용입니다. Word는 한국어를 어절 단위로 줄을 나눠 쪽 수가 한두 쪽 늘 수 있습니다.
- **각주 구분선**(v2.0): 본문과 각주 사이 선을 학회 양식대로(5 cm·2 cm·단의 1/3·단 전체, 굵기·색) 넣습니다. 설명은 [docs/v2.0_설계.md](v2.0_설계.md).
- **사용법·도움말** 페이지에 전체 설명과 문의처.
- **화면 그림**: 빈 화면(원고를 넣기 전), 처음 사용 안내(투고처를 고르기 전, 닫을 수 있음), 투고 일정 머리 띠, 변환 완료 카드(쪽수·각주·표 수와 저장 단추), 휴대폰 첫 화면(엔진을 불러오는 동안), 소개 페이지 첫 화면 띠. 그림은 Codex CLI 그림 생성으로 만들었고 지시문은 `assets/prompts.json`, 다시 뽑기는 `node tools/gen_assets.mjs <이름>`(원본 PNG는 `assets/raw/`, git 제외). 앱에는 줄인 JPG(`assets/img/`, 합쳐 약 200KB)를 빌드가 data: 주소로 넣습니다.
- **휴대폰**: 좁은 화면에서는 위쪽 앱 막대와 서랍(메뉴·투고처), 아래쪽 고정 버튼 막대(설정·적용·저장), ‘원고 구조 ↔ 결과 미리보기’ 전환으로 바뀝니다. 원고는 파일 앱·드라이브에서 고르고(형식 제한 없이 고른 뒤 확인), 결과는 저장하거나 ▾ 메뉴의 ‘공유하기’로 파일 앱·메신저에 보냅니다. 웹 배포본은 **홈 화면에 추가**하면 앱처럼 설치되고 한 번 연 뒤에는 인터넷 없이 열립니다(서비스 워커 캐시). 투고 일정은 카드로, 학회 정보의 탭은 옆으로 넘겨 봅니다.

**표·그림**: 원고의 표·그림을 그대로 옮깁니다. 한글 원고는 표·그림·도형·수식 개체를 통째로 옮기고(칸 너비·합친 칸·테두리·음영·캡션과 자동 번호), Word 원고는 표(합친 칸·음영·테두리)와 그림을 한글 표·그림으로 새로 만듭니다. 칸 안 글은 학회 본문 글꼴로, 캡션은 학회의 표·그림 제목 모양으로 바꾸고, 판면보다 넓은 표·그림은 폭을 줄입니다(나란한 그림은 합친 폭 기준). 표 칸 안 각주는 제자리에 두고 본문 각주와 번호를 이어 매기며, 캡션 안 각주는 한글이 쪽 아래에 찍지 않으므로 표·그림 바로 뒤로 옮깁니다. 표 위·아래의 ‘<표 1> …’ 제목과 ‘자료: …’·‘주: …’ 주석 문단은 각각 표·그림 제목, 표·그림 주석 역할로 잡고, 앞부분의 저자 정보 표처럼 놓인 자리의 묶음을 따릅니다.

변환하지 않는 것: Word 원고의 글상자·차트·수식(개수만 경고), 머리말·꼬리말. 변환 뒤 한글에서 넣습니다.

## 보안·개인정보

- 사용량은 두 가지만 셉니다. GitHub Releases의 배포본 내려받기 횟수, 그리고 배포 주소 첫 화면(소개 페이지)의 방문 수(쿠키 없는 hits.sh 집계 이미지)입니다. 변환기 HTML 자체는 아무것도 밖으로 보내지 않습니다. 맨 위 배지에서 바로 보이고, 버전별 숫자는 `node tools/usage.mjs`로 봅니다. 웹에서 연 변환기 화면은 세지 않습니다(원고를 다루는 화면에서는 어떤 외부 접속도 하지 않기 때문).

- 원고·결과는 브라우저 메모리에서만 처리되며 파일을 닫으면 사라집니다. 서버·외부 전송·AI 호출이 없습니다.
- 남는 것: 사용자가 추가한 학회·바탕틀, 설정값, 직접 입력한 마감(localStorage). 학회 추가 화면의 "사용자 데이터 초기화"로 지웁니다.
- 가져오는 JSON은 검증을 거치며, 내장 학회·바탕틀을 덮어쓸 수 없고 `http(s)://`가 아닌 투고처 주소는 버립니다.
- 입력 상한: 파일 64 MB, DOCX·HWPX 내부 XML 48 MB, 문단 2만 개, HWPX 한 문단 20만 자, 텍스트 600만 자.
- TXT·MD 표기: 각주 `[^1]` … `[^1]: 내용`(정의는 파일 끝에 모아 쓰고, 정의 아래 네 칸 들여 쓴 줄은 같은 각주의 다음 문단 — 본문 문단은 들여 쓰지 않음), 강조 `*기울임*`·`**굵게**`(낱말 경계에서만 — 저자 이름 뒤 `*` 표시는 글자로 남음), 장 제목 `#`, 인용 `>`.

## English — using tugotl

### What tugotl is and how to start

**tugotl** (투고틀, “submission frame”) reformats a scholarly manuscript to the house style of a Korean academic journal listed in the **KCI** (Korea Citation Index). It is meant for anyone submitting to Korean humanities journals, including researchers outside Korea who write in Korean or English but do not work in Hangul (HWP), the word processor most Korean journals require.

- **Input:** HWP · HWPX · DOCX · TXT · MD. **Output:** an HWP (and HWPX) file laid out in the journal’s own template or published specifications: paper size, margins, fonts, sizes, line spacing, footnote style, section order, abstract and keyword placement, tables and figures.
- **Rules only, no AI.** The text of your paper is never rewritten. Only citation details in footnotes and references are normalised to the journal’s rules (page units such as 쪽/면/p./pp., page-range marks such as `~` or `-`, title brackets 「」『』), and each of those can be switched off.
- **Private by design.** Everything runs inside your browser from a single offline HTML file. Nothing is uploaded, and no server or AI service is involved.
- **Journal data:** submission system links (most use JAMS), deadlines, fees, length limits, required forms, and footnote/reference rules for every built-in journal, collected from each society’s official regulations.

**Quick start:** download **[tugotl.html](https://github.com/fansenryu-cmd/tugotl/releases/latest/download/tugotl.html)** (about 30 MB) and open it in Chrome or Edge, or use it online at **https://fansenryu-cmd.github.io/tugotl/** (it can be installed on a phone with “Add to Home Screen” and then works offline). Pick the journal, drop your manuscript, press **적용 (Apply)**, check the preview, and press **저장 (Save)**. The interface is in Korean; the steps are the same four buttons every time.

### Screen and flow

Choose the target journal in the left sidebar (on a phone, in the drawer). Drop or pick the manuscript: paragraph roles (title, abstract, keywords, headings, body, block quotes, references, English abstract) are recognised and can be corrected one by one. **Apply** shows a page preview, an errata sheet (footnote citations checked against the reference list), a list of every change, and a pre-submission checklist; **Save** writes the HWP. Tables and figures are carried over with their captions; footnotes inside table cells keep running numbers with the body. Settings are limited to six switches (citation style, section reordering, anonymised copy for review, keeping blank lines, errata, automatic table of contents). Not converted: text boxes, charts and equations from Word files, and running headers/footers.

### Privacy and security

Manuscripts and results stay in browser memory and disappear when the page is closed. The only things stored (in the browser’s localStorage) are journals you added yourself, settings and deadlines you typed in. Usage is counted in exactly two places: release downloads on GitHub and visits to the landing page (a cookie-free hits.sh image). Both are shown in the badges at the top; per-release numbers come from `node tools/usage.mjs`. The converter page itself is never counted, because it makes no outside connection at all (its Content Security Policy blocks it).
