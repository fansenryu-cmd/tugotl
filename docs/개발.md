# 투고틀 개발 안내

변환 원리, 빌드·검증 도구, 코드 구조, 학회 추가 방법. *English follows the Korean.*

## 왜 이렇게 만들었나

- 학회마다 양식이 다르고 자주 바뀌어 매번 손으로 맞추는 일이 반복됩니다. 그 일을 **규칙**으로 고정해 두고 싶었습니다.
- 논문 원고는 심사 전 비공개 자료입니다. 그래서 **서버도, AI도, 전송도 없이** 브라우저 메모리 안에서만 처리합니다.
- 학회 규정은 그대로 따라야 합니다. 글꼴·크기·여백은 프로그램이 고르지 않고 **학회 양식 파일과 규정 수치**를 씁니다.

## 변환 원리

1. 바탕틀 .hwp를 rhwp로 열어 용지·여백·스타일·각주 설정을 읽습니다.
2. 학회 데이터(`src/journals.js`)의 `template.roles`가 역할마다 바탕틀의 **예시 문단 번호**(`para`, 여러 구역이면 `sec`) 또는 **스타일 이름**(`style`)을 가리킵니다. 그 문단의 문단 모양·글자 모양 ID를 읽어 둡니다.
3. 바탕틀 본문을 비우고 HWPX로 내보낸 뒤, 원고 블록을 역할 순서대로 **HWPX XML로 직접** 써 넣습니다(문단·런·각주·강조·붉은 표시). 다시 읽어 HWP로 저장합니다.
4. 바탕틀이 없는 학회는 규정 수치(`format`) 또는 일반 양식(`GENERIC_FORMAT`)으로 빈 문서에 서식을 만듭니다.
5. 구조 인식(`src/structure.js`), 서지 변환(`src/cite.js`), 정오표(`src/errata.js`)는 전부 정규식과 규칙입니다.
6. 저장 직후 HWP의 각주 모양 레코드를 한글이 읽는 배치로 고칩니다(`src/hwpfix.js`, rhwp 0.8.7의 구분선 길이 저장 결함 보완).
7. Word(DOCX)는 완성된 HWPX를 읽어 같은 서식의 Word 문서로 옮깁니다(`src/hwpx2docx.js`).

## 개발

```bash
npm install
node tools/build.mjs            # dist/투고틀.html·dist/tugotl.html (같은 배포본, CSP·SHA-256) + dist/dev.html (외부 파일 참조, 개발용)
node tools/usage.mjs            # Release 내려받기 횟수
node tools/pipeline_test.mjs    # 46건 회귀: 파싱→인식→생성→재로드
node tools/convert.mjs <원고> <학회id,...> --quiet   # 실원고 대조(누락 문단·각주·강조)
node tools/batch.mjs --out tests/report.json          # 원고 × 학회 대량 집계
node tools/overlap_check.mjs <hwp…>                   # 미리보기 각주 겹침 측정
node tools/export_journal_folders.mjs <폴더>           # 학회별 참고 폴더(바탕틀·규정·서식·요약 md)
python tools/pdf_profile.py <학술지.pdf> --json a.json      # 학술지 PDF의 조판 수치(용지·여백·글꼴·크기·줄간격)
node tools/output_profile.mjs <산출.hwp> --json b.json      # 산출물의 같은 수치
python tools/sample_compare.py <프로파일 폴더>               # 학회별로 나란히 비교
node tools/verify_matrix.mjs --md docs/검증매트릭스.md      # 원고 × 학회 전수 재검증(체재·역할별 서식)
node tools/footnote_shape_check.mjs <원고>                # 각주 구분선 회귀 검사(HWP 각주 모양 레코드·Word 각주 수)
node tools/font_inventory.mjs --md docs/글꼴안내.md          # 학회별 필요 글꼴 표
python -m http.server 8787      # dev.html은 서버에서 열어야 함
```

## 학회 추가·수정

`src/journals.js`의 항목을 복사해 고치거나, 앱의 **학회 추가**에 JSON을 붙여 넣습니다. 핵심은 `template.roles`와 `structure`, `footnote.pageUnit`, `blanks`입니다. 바탕틀 문단 번호는 학회 추가 화면에 .hwp를 넣으면 목록으로 보여 줍니다. 내장 학회 id와 같은 id, 내장 바탕틀과 같은 키는 받지 않습니다.

학회 규정이 바뀌었거나 양식 파일이 새로 나왔다면 이슈로 알려 주세요. 규정 전문이나 양식 파일을 함께 올려 주시면 반영이 빠릅니다.

## English — development

### Why

Every society has its own template and the templates change often, so authors re-format the same paper by hand for each submission. tugotl fixes that work into rules. Manuscripts under review are confidential, so the program has no server, no AI and no network access. Fonts, sizes and margins are never chosen by the program; they come from the society’s template file or its published numbers.

### How the conversion works

The journal’s template HWP is opened with [rhwp](https://github.com/edwardkim/rhwp) (an HWP engine compiled to WebAssembly) to read page setup, styles and footnote settings. Each role points to an example paragraph or a named style in the template. The template body is emptied, the manuscript is written into it as HWPX XML role by role, and the result is reloaded and saved as HWP. Journals without a template file use their published numbers or a generic layout. Role recognition, citation conversion and the errata check are regular expressions and rules.

### Adding or correcting a journal

Copy an entry in `src/journals.js`, or paste a JSON entry into the app’s **학회 추가 (Add journal)** screen (stored only in that browser, with export and import). If a society’s rules or template have changed, please open an issue with the regulation text or template file attached.
