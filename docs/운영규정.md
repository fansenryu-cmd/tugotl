# 투고틀 운영 규정 (감사·수정 에이전트 공통 브리프)

이 프로그램은 가장 엄밀하게 규칙을 준수해야 하는 학자들을 위한 오픈 소스 프로그램이다. 이 프로그램의 운영 규정은 여러 차원에서 보호되어야 한다. 모든 감사·검증·수정 작업은 아래 규정을 전제로 한다.

1. **원고의 내용이 유실되거나 누락되면 안 된다.** 특히 DOCX·한글(HWP/HWPX)·옛한글 입력기 등 고전 한글 입력, 외국 문자 표기(프랑스어·독일어·일본어·중국어 등), 특수 기호, 문장부호와 띄어쓰기 같은 스타일 요소가 변환 과정에서 변형되거나 빠질 우려가 있다. 이런 취약점은 가급적 다양한 방식으로 재현해 찾아야 한다. 검증은 "원고 → 변환 → 산출물 재파싱 → 원고와 글자 단위 대조"를 기본으로 한다(`tools/convert.mjs`).
2. **각주·편집 양식·참고문헌·요약(초록)·개요와 목차의 형식이 다르면 투고 접수가 아예 불가한 학회가 있다.** 이 부분은 최고 수준의 엄격함으로 점검한다. 학회 데이터(`src/journals.js`)의 체재 순서·쪽수 단위·빈 줄·용지·글꼴·크기·줄간격이 산출물에 그대로 반영되는지 산출 HWP를 열어(`tools/outcheck.mjs`, `tools/probe.mjs`) 대조한다.
3. **취약점은 프로그램을 망가뜨리기 위해서가 아니라 개선하기 위해 찾는다.** 감사 결과는 보고서로 작성하고, 수정 아이디어를 함께 제안한다. 제안이 합당하면 팀장(Fable)이 수정을 진행한다. 수정이 토큰 자원을 많이 쓰지 않는 영역은 팀장이 각 에이전트에게 분할해 지시할 수 있고, ASTRA의 특성을 살릴 수 있는 작업은 ASTRA에게 맡길 수 있다. 감사 에이전트는 `src/`, `dist/`, `release/`, `templates/`, `forms/`를 직접 수정하지 않는다.
4. **README와 GitHub 저장소 내용은 변경이 생기는 즉시 갱신한다.** 감사 반영·기능 추가·데이터 수정은 그때그때 커밋·푸시한다.
5. **배포본 HTML(`release/투고틀.html`)은 새 빌드가 나올 때마다 GitHub main에 갱신한다.** `release/투고틀.sha256`과 `gh-pages`도 함께 갱신한다.
6. **버전은 따로 표기하지 않는다.** 첫 배포 때 v1.0이라고 한 번 명시한다(그 뒤로는 커밋 해시와 SHA-256으로 식별).

## 감사 보고서 형식
요약(점수·판정·즉시 고칠 것) → 중요도순 발견(파일:줄, 재현 명령, 기대/실제, 수정안 코드 조각) → 실행한 명령과 수치. 보고서는 `docs/audit/review_<에이전트>.md`, 대응 기록은 `docs/audit/response_<날짜>.md`.

## 점검 항목 (최소)
- 내용 보존: 본문·각주 글자 단위 대조, 각주 위치, 강조(굵게·기울임·밑줄·위첨자), 특수 문자(옛한글 자모·한자·일본어·가나·라틴 확장·수학 기호·겹낫표 PUA), 문장부호·공백(전각 공백·줄바꿈·탭).
- 형식 준수: 체재 순서(`structure`), 쪽수 단위(`footnote.pageUnit`), 빈 줄(`blanks`), 용지·여백·글꼴·크기·줄간격(`format`/바탕틀 역할), 참고문헌 분류, 초록·주제어 위치, 목차.
- 견고성: 비정상·대용량 입력에 대한 오류 메시지와 처리 시간 상한, 사용자 데이터 검증, 외부 링크 주소 검증.
- 정오표(`src/errata.js`): 오탐·누락.
